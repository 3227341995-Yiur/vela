WHAT IS MEASURED, AND AGAINST WHAT
  axis 1  `vm.exe parse <file>` prints every struct / field / def / param with the name, mut and
          type the compiler itself writes, and `vm.exe lex <file>` prints the compiler's own line
          for every token.  For every declaration in the corpus, the hover at that declaration's
          name is held against that dump: kind, the parameter names in order with their types and
          their mut, the return type, the struct it belongs to, the line, and a struct's fields.
  axis 2  SPEC.md section 8 (read by DeclReader, which shares no code with the plugin) is the
          authority for the parameter names a builtin's hover prints.
  axis 3  every identifier in the compiler's own token stream that this file does not declare and
          the language does not provide must be hovered as NOTHING.
  axis 4  for each builtin, a program is written that makes the call its signature claims and
          `vm.exe check` is asked to accept it; a control program is compiled first, so "control
          accepted + builtin refused" means the signature is wrong and "control refused" means the
          harness is.
  a row = one hovered symbol; a row counts once however many of its claims disagree.
  Nothing here reads the hover through the hover's own model: the oracle is the compiler, SPEC.md,
  or the absence of any declaration.

WHAT THE HOVER NOW SAYS (and what it refuses to say)
  struct      `struct Vec2` + its fields with their types + one sentence
  def/method  the signature as written + every parameter with its type (and `mut`) + the return
              type + the struct it is a method of + one sentence
  field       `x: float` + which struct it belongs to
  param       `mut k: float` + which callable declares it
  builtin     the model's own signature + its own prose sentence + the parameters with their types
  unknown     nothing at all: a name this file does not declare and the language does not provide
              gets no kind, no signature and no sentence
  the one sentence for a name a FILE declares is built from what the model records (kind, owner,
  return type, parameter count) -- the model holds no prose for user code and none is invented;
  the only prose anywhere is a builtin's `prose` field in VelaModel.BUILTINS, used as written.
  A parameter list the model cannot read draws NO names, and the hover says so in words.
