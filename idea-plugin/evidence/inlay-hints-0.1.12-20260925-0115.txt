Every parameter-name hint was painted once per PSI element, and nothing here measured it   (0.1.12,
2026-09-25 01:15)

WHAT THIS FILE IS
=================

A defect the owner found by *looking at the editor* -- a screenshot of `ide-demo/tour.vel` with each
call's parameter label repeated until it ran off the line -- and the measurement that had been
missing underneath it.  Both matter, and they matter together: every hints number this plugin had
was green while the screen was wrong, because all four hints tools measure the *list*
(`VelaHints.parameterHints`) and none of them drove the object the platform actually calls.

The defect
    `VelaParameterNameInlayHintsCollector.collect` ignored the element it was handed, registered
    the whole file's hint list on every call, and returned `true` -- which is the platform's
    "keep walking into the children".  So each hint was registered once per PSI element:
    `ide-demo/tour.vel` has 7 hints and 490 elements, and the editor was asked to draw the same
    seven labels 490 times each.

The fix
    One paint per file, then stop the walk: a local flag makes the first call paint and every
    later call a no-op, and the return value is `false` so the platform does not descend at all.
    The offsets are document offsets, so it does not matter which element the first call arrives
    with.

WHY NO EXISTING TOOL COULD HAVE SAID SO
    `HintDiff`, `HintShapes`, `HintTruth` and `ParamNames` all call
    `VelaHints.INSTANCE.parameterHints(text, text.length())` and judge that list -- labels,
    ranges, shapes, truncations, duplicates.  The list was right; the *drawing* was multiplied by
    the element count.  `InlayProbe` is new here and drives the missing layer:
    `VelaParameterNameInlayHintsProvider.getCollectorFor(file, editor, settings, sink)`'s
    collector, over the file's real PSI tree (built through the platform's own `PsiBuilderImpl`,
    the same replay `psi-tree-diff.ps1` uses), with a recording `InlayHintsSink` counting every
    `addInlineElement`.

WHAT IS NOT MEASURED, SAID PLAINLY
==================================

* No IDE was started.  The sink here is a recording `java.lang.reflect.Proxy` for
  `InlayHintsSink`, the editor is a proxy, and the walk is this tool's implementation of the
  contract `FactoryInlayHintsCollector.collect`'s `Boolean` describes (the root first, children
  while a call returns `true`).  What is measured is *what the collector registers*; what a
  running IDEA paints is not, and the screenshot in the 0.1.12 changelog entry is the editor half
  of the evidence -- it is why this file exists, and it is not a substitute for the number.
* One consequence of the fix is visible in the after column and worth naming rather than hiding:
  the walk now stops at `elements 1`, because the first call paints the whole file and returns
  `false`.  That is the fix working, not the walk being skipped -- `registered` would be 0 if the
  collector had never been called at all, and it is 7 on the file with 7 hints.
* `InlayProbe` is now in `harness.ps1`'s tool list, so a run of the whole harness measures it;
  when it was written it was reached through `tools\run-harness.ps1 -Class InlayProbe`, and either
  way the exit code is the verdict (0 pass, 1 the invariant broke).
