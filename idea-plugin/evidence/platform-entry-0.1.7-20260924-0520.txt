THE MEASUREMENT SHOWN TO FAIL, AND THE THREE DEFECTS IT FOUND
=============================================================

Every section asks its own comparators to fire, on a real corpus position, before their zeros
are read: a member of the compiler's list dropped from the answer and a name nothing declares
added to it (row 7); the item's argument index moved by one, the drawn parameter list corrupted

All of them are caught; the raw lines are in the log below, and `PlatformEntry` exits 3 if any
one of them is not.

Running it found three real defects, all three in the plugin, and all three are fixed in 0.1.7:

  1. ROW 7 -- THE BUILTIN TABLE OUTRANKED THE FILE'S OWN DECLARATION.
     `tests/build/extern/extern_c_probe.vel` and three more files declare `extern c def abs(x: float)`.
     At the end of those files the offered `abs` was the *language's* builtin entry, whose
     template is `abs(n)`, and the dedupe then suppressed the file's own `abs`, so the inserted
     call named a parameter that declaration does not have:

         0.1.6, same tool, same corpus, harness already correct:
           4 position(s) of 2089 judged are wrong
           tests/build/extern/extern_c_probe.vel: `abs` template `(n)` names [n], and the
             declaration names [x]
           ... and the same row for tests/probes/extern_calls_as_declared.vel,
               extern_constant_fits_declared_kind.vel, extern_declared_after_the_call.vel
         0.1.7: 0.

     The rule was already written down twice in this plugin (`VelaTargets.declaredParameterNames`
     consults the language's table only for a name the file does not write, and
     `VelaInlayHints.parameterHints` follows it); the completion did not.  `VelaCompletion.offer`
     now skips a builtin whose name the file declares as a function, method or struct.

  2. ROW 9 -- THE POPUP EMPHASISED THE PARAMETER THE CARET WAS IN WHEN IT OPENED.
     `updateUI` draws from `hint.index`, and only `findElementForParameterInfo` ever set it, so
     moving the caret inside an open call told the platform a new index (`setCurrentParameter`)
     and told the drawn string nothing:

         0.1.6: emphasis 690 wrong, index 23 wrong of 2678 judged, e.g.
           tests/llvm-shapes/str_two_params.vel:6 `f(` argument 1 is bound to `b` by the compiler
             and the popup emphasises `a` in `a, b -> None`
           tests/probes/capture_probe.vel:46 `cap(` argument 1 is bound to `out` ... emphasises `cmd`
           tests/probes/capture_probe.vel:60 `cap(` caret at argument 1 (offset 2289) and
             setCurrentParameter was given 0
         0.1.7: 0.

     Two things were wrong in one line.  `callAt(context.offset)` reads the caret's *own line*, so
     on the second line of a call whose argument list spans lines (`cap(a,\n  b)`) it answers
     nothing and the index stayed at 0 -- the call's `(` now travels on the item, and counting
     from it works on every line.  And the item's index was never refreshed; it is now written
     back in `updateParameterInfo`, which is what makes the emphasis follow the caret.

  3. ROW 9 -- A METHOD'S RECEIVER PARAMETER WAS DRAWN AND EMPHASISED.
     The popup drew the declaration's parameter list *as written*, including a method's leading
     `self`, while the index counts the parentheses' arguments -- so every method call with a

     popup now does too -- including the declaration whose only parameter is the receiver, where
     the honest list is empty and `p.manhattan()` no longer emphasises `self`.

WHAT THE FIRST RUNS OF THIS TOOL GOT WRONG (the harness's own defects, found and fixed)
=======================================================================================

Written down because a tool whose own numbers moved is the reason to trust the last ones:

  * THE FIRST RUN REPORTED 648 OF 1009 ROW-9 WRONGS BECAUSE THE HARNESS PUT THE CARET ONE
    CHARACTER TOO FAR RIGHT.  A string literal's node covers its contents (`"a"` starts at `a`),
    so a caret placed there is *inside a string* -- and `callAt` answers null for that by design
    ("the caret is inside text, not code"), so no popup opened and the harness blamed the plugin.
    The caret is now placed on the literal's opening quote, which is the argument's own start.
    `HintDiff` makes the same distinction for the same reason.
  * THE FIRST RUN REPORTED 22 ROW-19 WRONGS FOR `print(argc())`: deleting the *inner* `)` leaves
    the *outer* one as the next character, and the honest answer there is "write nothing" --
    which is a different family of this same tool, not a wrong answer.  The shadowed case is now
    judged by that family's criterion.
  * THE FIRST VERSION OF ROW 9's CONTROL DID NOT FIRE: it "corrupted" a one-parameter declaration
    by reversing the list, and a reversed one-element list is the same list.  The control now
    replaces a name (and reverses when there are two or more).
  * AND ONE AFTER THE FIX: `ParameterHint` gained a field in 0.1.7, the control could no longer
    construct one, and it reported "A COMPARATOR CANNOT FIRE" -- the control's reflection was
    wrong, not the comparator.  It looks the constructor up by arity now.
