The retired rule, and the two that remain: `VelaStringConcatenation` in 0.1.11   (2026-09-25 00:50)

WHAT THIS FILE IS
=================

The language learned `+` on two `str`s and `+=` on a `mut s: str` (`SPEC.md` 1.5, landed in the
compiler on 2026-09-24, commit 4f06467).  The plugin had a rule that keyed on the refusal which made
that illegal -- `type error: string concatenation is not implemented in Vela 0.1` -- and offered
`concat(a, b)` as the repair.  That refusal cannot be produced any more, so the rule could not fire
honestly: either it never fired, or it fired wrongly on a legal program.  It is retired in 0.1.11 --
the class, its walk and the two helpers only it asked for -- together with the entries in the harness
that had been written for it, and the plugin registers two `localInspection` rules where it
registered three.

This file is the evidence for that round: the descriptor as it stands, the harness run against the
compiler that carries `+` on strings, and the verifier's own registration and version checks.  Every
number below was measured on this machine on 2026-09-25; nothing here is carried over from 0.1.10.

Both programs are accepted, and `SPEC.md` 8's `concat` row says they lower to the same runtime call.
A rule that reports one of them is not reporting a language error: it is expressing a preference the
compiler does not have, with a fix that rewrites a working program.  That is the whole argument for
retiring it instead of inverting it into a style rule (`concat(a, b)` -> `a + b`), and it is written
in `VelaInspections.kt` where the rule used to be, in `plugin.xml` where its registration used to be,
and above the retired tool in `InspectionProbe.java`.
