3. 不该消除的检查（消除就是不安全）
-----------------------------------
- 判据纪律：只有 `ck_iv_expr`（1869-1994）能给出**两端都已知**（lok==1 且 hik==1）的区间，
  且该区间与数组长度（`unpack_len(binding_kind)`，见 ck_index:1250、ck_iv_expr:1981）
  比较通过，才允许置位；任一端未知就必须保留。绝不能用 `ck_match_linear`(2298-2320) 的单射结论。
- (a) 需要**条件收紧**才能得出的上界：`while i < 10 { a[i] }` over `Array[int,8]`（我的反例，
  §4）。i 的区间是 [0,9]，9 ≥ 8，本来就证不出；DESIGN.md §3.1（162-167）的失效规则
  （循环内被赋值的变量在入口处变未知）就是防"跨回边用陈旧事实"的。
- (b) sieve 的 `comp[i]`（源 7，C:18）：上界来自非线性条件 `i*i < n`（SPEC §6.1 标"未实现"），
  且 `n` 是 mut int 局部 —— ck_iv_expr 对名字只查区间环境（1888-1907），**没有常量传播**，
  既没有 i 的区间也没有 n 的值。保留。
- (c) sieve 的 `comp[j]`（源 10，C:22，**热循环**）：j 初值 `i*i`，体内 `j += i` →
  入口失效规则把 j 打成未知；唯一可能的上界来自条件 `j < n`（条件收紧），下界要跨回边做不动点。
  现在都做不到。**这是最容易被错误消除的一处**：错消后 j 会越界写堆，程序不 panic 而是继续跑（静默）。
- (d) run_bench 插入排序内层（C:352-362，源 398-408）：`v[j]`(401)、`v[j+1]`(404)、`v[j]`(404)。
  j+1 的上界要 `j <= i-1 <= n-1`（跨两层循环 + 条件），j 的下界要 `j >= 0`，且 `j -= 1` 在回边上失效。保留。
- (e) run_bench 计时循环 `v[i]`（C:390，源 433）：`i < reps`，reps 是运行时参数；保留。
- (f) 常量越界不应"消除"而应**拒绝**（已实现，§4 末尾证据）。

(ii) 如果验收用 clang 量，会得到"已经平/赢"的假象，看不出 P3 的效果。

6. 我测不了的，以及为什么
-------------------------
6.1 区间分析的**实际结论**：没有 `vm.exe iv` 探针（usage 只有
    lex|count|parse|nodes|emit-c|run|check|debug|build|emit-llvm|build-llvm，11 个模式里没有它），
    check.vel 运行时不打印区间。§2 里"某处区间是多少"是**读代码 + 可观察代理**得出的
    （`#pragma omp parallel for` 存在 = ck_pcol 走过并行体），不是直接观测。要可证伪必须先做 item 3 的探针。
6.2 官方 harness 的数字（tools\bench.ps1 / RESULTS.md 重冻）：需要 vm.exe build 或 tools\build.ps1，被禁。
6.3 MSVC 下"删除检查后"的时间（与 0.543/0.177/0.181 那张阶梯同口径）：同样被禁；clang 给了反向结论，不能替。
6.4 check.vel 行号不稳定：开工时（01:46:50）116837 B，01:47:05 变成 120272 B；期间我的 grep 与 read
    拿到**不一致的行号**（同一个函数差 81 行）。本报告所有引用钉在快照
    sha256 38BE1B01…（120272 B、3305 行、mtime 2026-09-24 01:47:05），20 秒后与收尾两次复核 hash 未变。
    **ELISION_PLAN.md 的行号与该快照全都对不上**：它写 ck_index:897-936（实际 1233-1279）、
    ck_match_linear:1841-1862（实际 2298-2320）、ck_parallel 的 iv/lb 局部 ~2400-2447（实际 2852-2855）。
    → 引用时请用**函数名**，行号以你自己那份为准。
6.5 `NF_NO_BOUNDS` / `NF_NO_OVERFLOW` 在仓库里**只出现在两份 ELISION_PLAN 文档**里
    （selfhost\ELISION_PLAN.md:75-76,198-199；ELISION_PLAN.zh-CN.md:47-48,98），

- P3 验收的字面目标（内层循环 0 bounds + 0 add_range）在**不需要 item 1** 的前提下可以完成 5/6：
