# tests/cases.txt — the corpus, one case per line:
#
#   <mode>  <name>  <path>
#
# mode      what must be true
# ------------------------------------------------------------------------------
# run       built by the compiler under test (which drives the host's C
#           compiler itself), executed, and *also* interpreted: both must print
#           tests/golden/<name>.out exactly
# refuse    `check` must fail with the first bytes of stderr equal to
#           tests/golden/<name>.err, and must write nothing to stdout
# panic     it must compile, and the program must then stop at run time with
#           tests/golden/<name>.err as the head of stderr; the interpreter must
#           stop too
# ok        `check` must accept it and report ok
# dumps     the digests of `lex`, `parse` and `emit-c` must all match
#           tests/golden/digests.txt — three checks, three digests, so a change
#           in the back end cannot hide behind an unchanged parser
# lex       one of those three on its own, for a file that cannot be parsed
# fixpoint  the compiler must build itself through its own driver, and the
#           compiler it built must write the C it wrote — byte for byte
#
# Every refusal here is a program Python or C++ would accept and misbehave on,
# and every `ok` is a program a conservative compiler would be wrong to refuse.
# The two halves are the point: a compiler that refuses one program too many is
# as broken as one that accepts one too few.

# ------------------------------------------- a C library, called from Vela
#
# The one language feature that reaches outside the language: `extern c` names a
# C function, the back end calls it, and the checker refuses the boundary it
# cannot describe honestly (a `str`, an array) instead of inventing one.
#
# Two cases, because there are two promises.  The compiled program must call
# `abs` and `sqrt` and print the right answers; the *interpreter* must refuse the
# same program and say why.  Vela has no FFI and is not going to grow one, so an
# interpreted program cannot reach a C library — that is a boundary the language
# states rather than a gap the suite hides, and it is asserted right here.

# --------------------------------------- the aliasing rule of `parallel for`
#
# An array the body **writes** may be read inside that loop only at the write's own
# index expression.  It is the language-level form of what Rust's `par_iter_mut`
# enforces by construction — an iteration is handed its own element and cannot
# reach another iteration's — and it is why `a[i] = a[i - 1] + 1` cannot be written
# here at all: before the rule existed that program compiled to
# `#pragma omp parallel for` and printed **nine different wrong values in twenty
# runs** (3, 7, 11, 15, 19, 27, 31, 51, 55) while the interpreter printed 63.
#
# Five cases, because a rule is only worth having if both directions are held: one
# program that must be refused, and four that must keep compiling — including the
# two shapes the benchmarks and ordinary accumulation depend on.
#
# These are NEW cases, written together with the rule, and their goldens have not
# been recorded yet.  `tools\refreeze.ps1` records them while keeping every
# existing `.out`/`.err` byte for byte (a golden is an expectation and must not be
# replaced by the compiler's own output).

refuse parallel_alias_cross_iteration        tests/probes/parallel_alias_cross_iteration.vel
run    parallel_alias_read_only              tests/probes/parallel_alias_read_only.vel
run    parallel_alias_read_any_index         tests/probes/parallel_alias_read_any_index.vel
run    parallel_alias_same_index             tests/probes/parallel_alias_same_index.vel
