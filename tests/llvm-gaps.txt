# Shapes the LLVM back end cannot compile yet.  These are GAPS, not designs.
#
# Read by `tools\llvm-column.ps1`, which judges the programs in `tests\llvm-shapes\`.
# Do not confuse this file with `tests\llvm-refusals.txt`:
#
#   * `tests\llvm-refusals.txt` records refusals that are PERMANENT AND INTENDED
#     (`parallel for`: LLVM IR has no OpenMP, and Vela will not ship a loop that says
#     it is parallel while running serially).  Those entries are supposed to stay.
#
#   * this file records refusals that are GAPS -- ordinary programs the other two
#     paths compile today.  Every entry here is work owed, and an entry that stops
#     being refused FAILS the run so that the progress gets recorded instead of
#     quietly becoming a hole in the ledger.
#
# `build` and `build-llvm` are the LLVM back end now, and `build-c` is the C one.
# While anything was listed in this file, the flip could not happen: it would have
# taken programs that compiled and refused them.  The file is empty, the flip is
# done, and the programs the LLVM back end still refuses are the seven
# `parallel for` rows -- refused *by design*, recorded in `llvm-refusals.txt`, and
# compiled by `build-c` from rows that say so in `tests\cases.txt`.
#
# Format, one per line:
#
#     <file name without .vel> | <substring the refusal must contain>

# CLOSED 2026-09-24: the string ABI.  Five rows stood here -- `str_param`,
# `str_two_params`, `mut_str_param`, `str_return`, `recursive_str` -- for a `str`
# crossing a user function's boundary in either direction.  A `str` is a 16-byte
# value that the Microsoft ABI passes by reference and returns through a hidden
# first pointer, and the back end now models exactly that: a `str` parameter
# arrives as a pointer and the callee copies the 16 bytes into a slot of its own
# (which is what the C back end's by-value `vela_str` parameter means), and a
# function that returns `str` is declared `void @f(ptr sret(%vela_str), ...)` with
# `vshim_fn_sret_param`, so the *caller* owns the storage and a call expression is
# worth the address of it -- the same "a `str` is a pointer to its 16 bytes" rule
# the rest of this back end follows, and what makes a recursive `str` function
# work.  An `extern c` declaration with a `str` on either side is still refused,
# deliberately: that ABI is somebody else's (`escape_extern_str_parameter_refused`,
# `escape_extern_str_return_refused` hold the C back end to the same refusal).

# CLOSED 2026-09-24, by the LLVM back end work: abs_builtin, pow_operator and
# struct_return (a `struct` result went out through the same hidden pointer a `str`
# result uses, and `**`/`abs` got the runtime's own exported helpers).
#
# CLOSED 2026-09-24, the last three: `array_param`, `array_of_str`,
# `inplace_element_update`.  **This file is now empty of open gaps** -- every shape in
# `tests\llvm-shapes\` compiles, and the tally reads `open gaps 0/0`.
#   * `array_param`: an array *argument* is the array's address (`ll_array_ptr`), which
#     is what the C back end's `int64_t* a` parameter already was -- and passing a
#     parameter array on to another function works, because a parameter is a local
#     binding with the array kind.
#   * `array_of_str`: `ll_esize` gives a `str` 16 bytes (the C back end's
#     `sizeof(vela_str)`), a `str` *element* reads as its address rather than a 16-byte
#     load (a `str` value here *is* that address), and an element store is the same
#     16-byte copy a `str` field gets (`ll_store_into`, which is what the old
#     `ll_field_store` is now called, because a field and an element are one problem).
#   * `inplace_element_update`: `a[i] += v` takes its destination address from
#     `ll_index_addr`, so the bounds check is in front of it exactly as the C back
#     end's hoisted check is, and the rest of the augmented-assignment path (load,
#     checked arithmetic, narrow store) is shared with the local case.
# A ledger that is empty is not a claim that the back end is finished, and the
# paragraph that used to stand here said so with an example that has since been
# closed: `build-llvm selfhost/vm.vel` used to stop at a builtin (`warn_str` was
# the first, by link order).  Measured 2026-09-24: it builds the compiler, and the
# compiler it built compiles a program -- `tools\selfhost-llvm.ps1`, which is the
# gate for exactly that, is green.
#
# What that gate and `tools\llvm-column.ps1` do *not* cover is still the honest
# shape of the remaining work: they compare the interpreter against the LLVM
# product for programs that both accept, so a construct the LLVM back end refuses
# is invisible unless a shape here names it.  That is what this file is for, and
# the next refusal found belongs here -- not in a sentence claiming the back end
# is complete because the list is empty.
