# Shapes the LLVM back end cannot compile yet.  These are GAPS, not designs.
#
# Read by `tools\llvm-column.ps1`, which judges the programs in `tests\llvm-shapes\`.
# Do not confuse this file with `tests\llvm-refusals.txt`:
#
#   * `tests\llvm-refusals.txt` records refusals that are PERMANENT AND INTENDED
#     (`parallel for`: LLVM IR has no OpenMP, and Vela will not ship a loop that says
#     it is parallel while running serially).  Those entries are supposed to stay.
#
#   * this file records refusals that are GAPS -- ordinary programs the other two
#     paths compile today.  Every entry here is work owed, and an entry that stops
#     being refused FAILS the run so that the progress gets recorded instead of
#     quietly becoming a hole in the ledger.
#
# `build-llvm` cannot replace `build` while anything is listed here: flipping the
# default would take programs that compile today and refuse them, which is the one
# outcome worse than still needing a C compiler.
#
# Format, one per line:
#
#     <file name without .vel> | <substring the refusal must contain>

# CLOSED 2026-09-24: the string ABI.  Five rows stood here -- `str_param`,
# `str_two_params`, `mut_str_param`, `str_return`, `recursive_str` -- for a `str`
# crossing a user function's boundary in either direction.  A `str` is a 16-byte
# value that the Microsoft ABI passes by reference and returns through a hidden
# first pointer, and the back end now models exactly that: a `str` parameter
# arrives as a pointer and the callee copies the 16 bytes into a slot of its own
# (which is what the C back end's by-value `vela_str` parameter means), and a
# function that returns `str` is declared `void @f(ptr sret(%vela_str), ...)` with
# `vshim_fn_sret_param`, so the *caller* owns the storage and a call expression is
# worth the address of it -- the same "a `str` is a pointer to its 16 bytes" rule
# the rest of this back end follows, and what makes a recursive `str` function
# work.  An `extern c` declaration with a `str` on either side is still refused,
# deliberately: that ABI is somebody else's (`escape_extern_str_parameter_refused`,
# `escape_extern_str_return_refused` hold the C back end to the same refusal).

# Arrays are passed as a pointer plus a length in the C back end.  The LLVM back end
# has no spelling for an array value, only for an element read and for `len(a)`.
array_param         | an array name is not a value the LLVM back end can read on its own
