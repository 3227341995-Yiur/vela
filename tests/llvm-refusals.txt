# Programs the LLVM back end refuses, deliberately, with the reason.
#
# Read by `tools\llvm-column.ps1`.  The rule is two-sided on purpose:
#
#   * a program in the corpus that this back end refuses must appear here, or the
#     run fails -- the back end is not allowed to grow silent holes;
#   * a program listed here that is NOT refused any more also fails the run --
#     an entry that is never pruned stops describing the back end, and from then
#     on it is decoration.
#
# Format, one per line:
#
#     <case name from tests/cases.txt> | <substring the refusal must contain>
#
# The substring is matched with .Contains(), so write plain text, not a pattern.

# LLVM IR has no OpenMP, and emitting the runtime ABI is out of scope for this
# back end.  A loop that says it is parallel while running serially is the one
# failure mode this project has promised never to ship, so this refusal is
# permanent and by design rather than a gap being worked on.
# See `selfhost/LLVM_PLAN.md`; the C back end compiles all seven of these.
parallel_for_correct             | is refused by the LLVM back end, deliberately
parallel_nested_2d               | is refused by the LLVM back end, deliberately
pure_call_inside_parallel        | is refused by the LLVM back end, deliberately
parallel_alias_read_only         | is refused by the LLVM back end, deliberately
parallel_alias_read_any_index    | is refused by the LLVM back end, deliberately
parallel_alias_same_index        | is refused by the LLVM back end, deliberately
parallel_alias_nested_rowmajor   | is refused by the LLVM back end, deliberately

# Enums were the second gap and they are closed now: `match`, a bare variant, a
# construction, an enum-returning function, an enum parameter, an enum binding and
# `errdefer`'s tag are all lowered (a payload cell is one `i64` for `int`, `float`,
# `i32`, `u8` and `bool`, and two for `str`).  The six lines that used to stand here
# went red as NO-LONGER-REFUSED one at a time, which is what the two-sided rule is
# for.
#
# One shape of enum is still refused, and it is a *limit of the cell layout* rather
# than a gap being worked on: an enum whose payload is itself an aggregate.  A
# payload cell is one `i64` (or the two halves of a `str`), so there is nowhere to
# put a struct or a nested enum by value -- a cell could only hold the address of
# one, and an address into a frame that has returned is a wrong answer rather than a
# refusal.  The C back end compiles it (its payload is a real union member of the
# nested type), so `enum_two_enums` stays a `run-c` row with this line as its other
# side.
enum_two_enums                   | an enum payload that is itself a struct or an enum is not compiled by the LLVM back end yet
